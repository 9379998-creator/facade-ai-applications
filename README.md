# Facade AI Applications

> **Прикладной искусственный интеллект для полного жизненного цикла фасадного проекта**  
> *Applied Artificial Intelligence for the Complete Lifecycle of a Building Facade Project*

---

## О проекте

**Facade AI Applications** — это долгосрочный проект и открытая интерактивная презентационная платформа, созданная для того, чтобы наглядно и простым языком объяснить участникам строительного процесса реальную роль специализированных приложений, инженерных алгоритмов и прикладного искусственного интеллекта в фасадной компании.

### Главная идея проекта:
> «Искусственный интеллект не должен становиться ещё одной сложной программой или обязательным чатом. Он должен работать внутри понятных отраслевых приложений. Сотрудник загружает документы или вводит данные, нажимает понятную кнопку, проверяет результат и получает таблицу, расчёт, документ, отчёт, предупреждение или управленческое решение».

### Для кого предназначен проект:
- Коммерческий отдел и сметчики;
- Конструкторский отдел и расчётчики;
- Отдел материально-технического снабжения;
- Служба логистики;
- Производство (цех обработки профиля и сборки);
- Строительная площадка (прорабы, бригадиры, шеф-монтаж);
- Руководители проектов (РП);
- Финансово-экономическая служба и бухгалтерия;
- Служба качества (ОТК) и инженеры ПТО;
- Топ-менеджмент и инвесторы.

## Сквозной синтетический объект: «Северный порт»

Все сценарии, алгоритмы и демонстрации построены вокруг сквозного **вымышленного типового московского строительного объекта «Северный порт»** (Northern Port).

### Почему используются только синтетические данные?
Репозиторий является публичным (`PUBLIC`). Использование реальных чертежей, смет и названий девелоперов нарушает соглашения о неразглашении (NDA), авторские права и коммерческую тайну. Синтетический проект позволяет безопасно моделировать сложные инженерные ситуации:
- Светопрозрачные стоечно-ригельные конструкции (СПК);
- Навесные вентилируемые фасады (НВФ) с кассетами и натуральным камнем;
- Межоконные пояса, примыкания и монтажные захватки.

Все числовые значения и параметры, не подтверждённые владельцем, строго помечены как **`TBD`** (To Be Determined).

## Честная классификация статусов реализации

В презентации и интерфейсе каждый модуль и кейс имеет строго фиксированный статус:

| Статус | Обозначение | Что это означает на практике |
|---|---|---|
| **WORKING** | Зелёный | Функция полностью реализована в коде, протестирована и доступна прямо сейчас |
| **PROTOTYPE** | Оранжевый | Интерактивный кликабельный прототип для демонстрации интерфейса и сценария |
| **CONCEPT** | Индиго | Проработанная целевая идея или алгоритмическая модель, ожидающая реализации |
| **TBD** | Серый | Параметр требует уточнения и сбора исходных данных |

> **Строгое правило**: Мы категорически не выдаём концепты за готовый софт и не придумываем неподтверждённые проценты «экономии бюджета».

## Отношение к проекту Launcher

Проект легковесного просмотрщика документации **Launcher** является отдельным направлением разработки. Его закрытый исходный код **не копируется** в данный репозиторий. В рамках проекта моделируются сценарии его применения через спецификации и открытые демонстрационные манифесты (см. `prototypes/launcher/`).

## Быстрый старт

### Требования к окружению:
- Node.js: версия 20+ (рекомендуется LTS 22+);
- npm: версия 10+;
- Git: версия 2.40+.

### Установка зависимостей:
```bash
npm install
```

### Запуск в режиме разработки:
```bash
npm run dev
```
После запуска откройте в браузере: `http://localhost:3000`

### Сборка для публикации (Production Build):
```bash
npm run build
```

## Проверки качества и безопасности

В проекте настроен строгий автоматический конвейер проверок:

```bash
# Запуск полного цикла проверок:
npm run validate

# Либо по отдельности:
npm run lint              # Проверка стиля кода ESLint
npm run typecheck         # Проверка типов TypeScript (tsc)
npm run test              # Модульные тесты компонентов (Vitest)
npm run test:e2e          # Сквозные тесты интерфейса (Playwright)
npm run validate:content  # Валидация JSON-схем контента через Zod
npm run scan:sensitive    # Сканер секретов, токенов и персональных данных
npm run check:large-files # Проверка размера файлов (>10MB)
```

## Как добавить новый кейс

1. Изучите Устав проекта и политику обращения с данными в папке `docs/`.
2. Создайте файл кейса в каталоге `content/cases/<имя-кейса>.json` в соответствии со схемой `BusinessCase`.
3. Запустите `npm run validate:content`, чтобы убедиться в корректности схемы.
4. Откройте Pull Request с ветки `feat/*` в `main`.
